Every error ran the same direction: the old approach under-counted, so it reported more headroom than existed. On Opus 5 it was worst — that model had no calibration entry at all and silently fell back to a default meant for an older tokenizer.

You can re-run the gate yourself with npm run test:tokenizer. It fails unless all 5,278 documents reproduce exactly, which matters because a tokenizer fails silently: it returns a plausible number rather than an error. Document-level parity is the only real evidence.

Install

Not on the Chrome Web Store yet, so it loads unpacked. Chromium browsers only — Firefox packaging is not done.

  1. Get the build

    Download the zip from Releases and unzip it. Or build from source:

    git clone https://github.com/x1vlcn/claude-context-meter
cd claude-context-meter
npm install && npm run build

  2. Open your browser's extensions page

    brave://extensions, chrome://extensions, or edge://extensions. Turn on Developer mode.

  3. Load unpacked

    Select the unzipped folder (or dist if you built from source). Open any conversation on claude.ai — the meter appears beside it.

Mobile: Brave for Android cannot load extensions from a folder, and the Claude Android app is native, so neither can run this today. Desktop only until the Web Store listing exists.

How it works

The extension reads the conversation payload claude.ai already fetches for itself, counts it locally, and renders the result. Nothing is uploaded, there are no analytics, and it talks to no server other than claude.ai.

Where the number comes from

Four sources, in strict order of trust. The panel always names the one in use.

measuredground truth

The server's own input_tokens from the response stream. When this is available, nothing is estimated.

exactlocal tokenizer

Every message tokenized with the ported Claude tokenizer. Exact per message; the conversation's framing overhead is the remaining unknown.

cachedprevious visit

The stored tally for this conversation, shown immediately on load so the meter never flashes empty while the payload is fetched.

approxfallback

A measured characters-per-token ratio, used only in the moment before the vocabulary finishes loading, or for a model released after the build. Always labelled.

The tokenizer

Claude's tokenizer is not published, and it is not BPE-merge based — it behaves like minimum-piece tokenization, so a count is the cheapest tiling of a marked stream over a vocabulary, with a UTF-8 byte floor for characters no piece covers. Word edges, capitalisation and byte fallback are written into that stream as markers before tiling, which is what the strip at the top of this page is showing.

The vocabulary and the tiling rules come from sanderland/ctok, Sander Land's reconstruction of it. This project ports that to JavaScript and ships the vocabulary as data fetched on demand — 205 KB for current models — rather than bundling a 2.7 MB foreign tokenizer that was wrong anyway.

What it can't do

Limits worth knowing

Exact tokenization fixed the part that could be fixed. These are the parts that remain estimates, and the panel labels them rather than folding them in silently.

The system prompt is an estimate

Claude's base system prompt and always-on tool definitions are not in any payload the browser can see. The default is approximately 28,000 tokens and is adjustable in Options. It is the single largest remaining source of error.

Project knowledge cannot be measured

Project documents are retrieved per turn by relevance, and the payload does not say which chunks were used. It is shown as a separate unmeasured line rather than guessed at.

Images are approximated

Image cost depends on dimensions the payload does not carry, so a flat per-image estimate is applied and marked approximate.

Conversation framing is not separately verified

The upstream tokenizer is validated on single messages. Per-message content is exact; the overhead of assembling many turns into one request is not independently confirmed, which is why a measured reading always outranks a local count.

Send feedback

Tell us when it's wrong

The panel has a feedback button. It sends what you type, plus — only if you leave the box ticked — meter diagnostics: version, model, window size, percentage, tokenizer mode, viewport. The panel shows you the exact payload before it goes.

It never sends conversation text, titles, ids, or the page URL. None of that is needed to reproduce a metering bug, and the extension asks for no network permission beyond claude.ai until a feedback endpoint is configured.

Bugs and feature requests are also welcome as GitHub issues.
